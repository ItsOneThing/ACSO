Lezione 1

Processi e parallelismo

Cap. P1 delle dispense Pelagatti — il sistema operativo come creatore di parallelismo e le system call per gestire i processi: fork, exit, wait, waitpid, exec.

1. Il sistema operativo

Definizione Il sistema operativo è un insieme di programmi (moduli software) che svolgono funzioni di servizio nel calcolatore. È la parte essenziale del software di sistema (o di base): non fa cose "applicative", ma fa da supporto alle applicazioni.

Il SO serve a:

  • offrire all'utente una macchina "virtuale" che esegue i suoi comandi, costruita sopra la macchina reale (di livello più basso);
  • offrire ai programmi (e quindi al programmatore) un insieme di servizi di sistema, che si invocano con le chiamate di sistema (system call);
  • controllare le risorse fisiche e creare/gestire il parallelismo.

2. Il SO come creatore di parallelismo

Esecuzione sequenziale

N programmi vengono eseguiti uno dopo l'altro: il programma i parte solo quando è finito il programma i−1.
✔ Nessuna interferenza tra programmi.
✘ Non basta per le esigenze reali: applicazioni distribuite, server multiutente, più applicazioni aperte dallo stesso utente.

Esecuzione parallela

Deve soddisfare due obiettivi in contrasto:
  • parallelismo;
  • virtualizzazione: ogni programma deve girare senza interferenze, come se avesse la macchina tutta per sé.

La soluzione: il SO crea dinamicamente tanti esecutori quanti sono i programmi da eseguire in parallelo. Questi esecutori si chiamano processi. Un processo è un esecutore completo.

Il SO sa creare processi indipendenti e fornisce al programmatore le system call per crearli ed eliminarli.

Multitasking Le slide mostrano (con figure) la pila utente → applicazioni → SO → hardware, e l'idea di SO multitasking: più processi attivi "contemporaneamente" sopra lo stesso hardware, con il SO che fa da intermediario.

3. Virtualizzazione delle risorse e system call

  • Se più processi vogliono usare contemporaneamente una risorsa reale condivisa, il SO gestisce il conflitto creando risorse virtuali e mettendo in coda i processi che la richiedono.
  • Per questo un programma non può accedere direttamente alle periferiche: deve usare le system call (es. le funzioni di I/O della libreria C, come printf, alla fine chiamano system call).
Programmazione di sistema Le tecniche per scrivere programmi utente che interagiscono strettamente con il SO usando le sue system call.

Categorie principali di system call:

  • gestione dei processi ← questa lezione
  • segnalazioni
  • gestione di file
  • gestione di direttori e file system
  • protezione
  • gestione di ora e data

4. Cos'è un processo

  • Un processo è un programma in esecuzione.
  • Ogni processo ha un PID (Process IDentifier): numero a 16 bit, unico, assegnato in sequenza da Linux alla creazione.
  • Ogni processo è creato da un altro processo, quindi ha un padre. Unica eccezione: init, il primo processo creato all'avvio del SO.

La memoria di un processo: tre segmenti

SegmentoContiene
Codice (text segment)il codice eseguibile del programma
Dati (user data segment)tutte le variabili: globali/statiche, locali (sullo stack), dinamiche (malloc)
Sistema (system data segment)dati gestiti dal SO e non dal programma, es. la tabella dei file aperti

Gerarchia di processi

Un padre può generare più figli, e ogni figlio può a sua volta generarne altri: si forma un albero.

6. Creare un processo: fork()

pid_t fork(void);
  • Crea un processo figlio identico e parallelo al padre: è una copia esatta del padre nell'istante della fork.
  • Vengono duplicati il segmento dati e il segmento di sistema: variabili, file aperti… sono copiati nel figlio. Da quel momento i due processi evolvono indipendentemente: se il figlio modifica una variabile, il padre non vede la modifica (e viceversa).
  • Entrambi ripartono dall'istruzione subito dopo la fork.
L'unica differenza: il valore restituito
  • nel padre → il PID del figlio appena creato (così il padre lo conosce); −1 in caso di errore;
  • nel figlio → 0.

Esempio base

#include <stdio.h>
#include <sys/types.h>

void main(int argc, char *argv[]) {
   pid_t pid;
   pid = fork();
   if (pid == 0) {                         /* processo figlio */
      printf("sono il processo figlio\n");
      exit();
   } else {                                /* processo padre */
      printf("sono il processo padre\n");
      exit();
   }
}

Output possibili:

sono il processo figlio
sono il processo padre
sono il processo padre
sono il processo figlio
Errore grave da evitare Dopo la fork padre e figlio evolvono in parallelo e scrivono sullo stesso standard output: l'ordine delle printf è casuale. Non bisogna mai supporre un ordine preciso di esecuzione tra due processi.

Esempio: generare 2 figli

void main() {
   pid_t pid1, pid2;
   pid1 = fork();
   if (pid1 == 0) {                              /* PRIMO FIGLIO */
      printf("FIGLIO 1: PID = %d\n", getpid());
      exit();
   } else {                                      /* PADRE */
      pid2 = fork();
      if (pid2 == 0) {                           /* SECONDO FIGLIO */
         printf("FIGLIO 2: PID = %d\n", getpid());
         exit();
      } else {                                   /* PADRE */
         printf("PADRE: PID = %d\n", getpid());
         printf("PADRE: PID DEL FIGLIO 1 = %d\n", pid1);
         printf("PADRE: PID DEL FIGLIO 2 = %d\n", pid2);
         exit();
      }
   }
}

La seconda fork è solo nel ramo del padre: così è il padre a creare entrambi i figli (sono "fratelli"). Il primo figlio fa exit subito e non esegue la seconda fork.

Trappola classica Se metti due fork() una dopo l'altra senza if, anche il primo figlio esegue la seconda fork: ottieni 4 processi in totale (in generale 2n con n fork in sequenza).

7. getpid() e getppid()

pid_t getpid(void);    // PID del processo che la chiama
pid_t getppid(void);   // PID del suo padre (parent)
void main() {
   pid_t pid;
   printf("Prima della fork: PID = %d\n", getpid());
   pid = fork();
   if (pid == 0) {
      printf("FIGLIO: PID = %d\n", getpid());           // PID del figlio
      printf("FIGLIO: PID DEL PADRE = %d\n", getppid()); // PID del padre
      exit();
   } else {
      printf("PADRE: PID = %d\n", getpid());            // PID del padre
      printf("PADRE: PID DEL FIGLIO = %d\n", pid);      // valore restituito dalla fork
      exit();
   }
}

Nota: "Prima della fork" e "PADRE: PID" stampano lo stesso numero; "FIGLIO: PID DEL PADRE" anche (se il padre è ancora vivo). "PADRE: PID DEL FIGLIO" = "FIGLIO: PID".

8. Terminare: exit()

void exit(int);
  • Termina il processo corrente (un processo può terminare anche senza exit, ad esempio arrivando alla fine del main).
  • L'intero passato è il codice di terminazione (exit code) ed è "restituito" al padre.
  • Convenzione: 0 = tutto ok, ≠ 0 = errore.
  • Se il padre è già terminato, il valore va all'interprete comandi del SO.

9. Aspettare un figlio: wait()

pid_t wait(int *);
  • Sospende il processo che la chiama finché un qualsiasi figlio termina.
  • Se un figlio è già terminato prima della wait, la wait ritorna subito.
  • Restituisce il PID del figlio terminato.
  • Nel parametro (passato per indirizzo) mette l'exit code del figlio moltiplicato per 256, cioè spostato negli 8 bit più significativi. Per leggerlo: stato / 256.
void main() {
   pid_t pid;
   int stato_exit, stato_wait;
   pid = fork();
   if (pid == 0) {                                   /* figlio */
      printf("sono il processo figlio con pid: %d\n", getpid());
      stato_exit = 5;
      exit(stato_exit);                              /* il figlio termina con codice 5 */
   } else {                                          /* padre */
      printf("Ho generato il processo figlio con pid %d\n", pid);
      pid = wait(&stato_wait);                       /* attende la fine del figlio */
      printf("Terminato il processo figlio %d con esito %d\n", pid, stato_wait / 256);
   }
}

Il padre stampa esito 5: stato_wait vale 5 × 256 = 1280. La riga "Terminato…" esce sempre per ultima, perché il padre la stampa solo dopo la wait.

10. Processi zombie

  1. Il figlio termina mentre il padre è già in wait → il figlio termina e il suo exit code passa al padre tramite la wait.
  2. Il figlio termina quando il padre non ha ancora chiamato wait → il figlio diventa uno zombie. Quando il padre chiamerà wait, lo stato dello zombie viene recuperato, lo zombie viene eliminato e la wait ritorna subito.
Processo zombie Un processo terminato ma non ancora "ripulito": il SO ne conserva lo stato di terminazione perché il padre possa ancora recuperarlo con wait.

11. Aspettare un figlio preciso: waitpid()

pid_t waitpid(pid_t pid, int *status, int options);
  • Come wait, ma aspetta il figlio con quel PID (non uno qualsiasi).
  • Se il figlio è già terminato, ritorna subito.
  • Restituisce il PID del figlio terminato; status riceve il codice di terminazione; options specifica altre opzioni.
my_pid = waitpid(pid, &status, 1);   /* il padre attende la fine di QUEL figlio */
printf("E' terminato il processo %d con esito %d\n", my_pid, status);

12. Cambiare programma: exec

exec sostituisce il programma in esecuzione con un altro (commutazione di codice): il processo resta lo stesso, ma smette subito di eseguire il vecchio programma e comincia il nuovo.

Cosa cambiaCosa NON cambia
segmento codice e segmento dati: presi dal file eseguibile indicatosegmento di sistema: file e socket restano aperti
il PID: è lo stesso processo

I parametri arrivano al nuovo programma con il meccanismo standard di main(argc, argv).

Sintassi di execl

int execl(char *path_programma, char *arg0, char *arg1, ..., char *argn);
  • path_programma: percorso completo dell'eseguibile da lanciare;
  • arg0: per convenzione il nome del programma;
  • l'ultimo argomento deve essere NULL (fine della lista);
  • restituisce −1 se fallisce. Se riesce, in pratica non ritorna mai: il vecchio codice non esiste più. Per questo l'istruzione dopo una execl viene eseguita solo in caso di errore.

argc e argv

  • argc: numero di parametri ricevuti;
  • argv: array di puntatori a stringhe; argv[0] è il nome del programma.
void main(int argc, char *argv[]) {
   int i;
   printf("ho ricevuto %i parametri\n", argc);
   for (i = 0; i < argc; i++)
      printf("parametro %i = %s\n", i, argv[i]);
}

Esempio: exec1 lancia main1

exec1

void main(int argc, char *argv[]) {
   char P0[] = "main1";
   char P1[] = "parametro1";
   char P2[] = "parametro2";
   printf("programma exec1 in esecuzione\n");
   execl("/esempi/main1", P0, P1, P2, NULL);
}

main1

void main(int argc, char *argv[]) {
   int i;
   printf("programma main1 in esecuzione\n");
   printf("ho ricevuto %d parametri\n", argc);
   for (i = 0; i < argc; i++)
      printf("il parametro %d e': %s\n", i, argv[i]);
}
$ ./exec1

13. fork + exec

  • exec non crea un processo nuovo: nell'esempio sopra, quando main1 termina, termina anche il processo che era exec1 (sono lo stesso processo).
  • Se voglio che il programma di partenza resti vivo, devo prima fare fork e poi exec nel figlio. Di solito il padre poi aspetta il figlio con wait.
  • È il modo standard per "eseguire un altro programma come una funzione": il chiamante continua nel padre, il figlio diventa il nuovo programma. (È esattamente quello che fa la shell quando lanci un comando.)
void main() {
   pid_t pid, chpid;
   pid = fork();
   if (pid == 0) {                                   /* FIGLIO */
      printf("FIGLIO: prima del cambio di codice\n");
      printf("FIGLIO: PID = %d\n", getpid());
      execl("./prog", "prog", NULL);
      printf("FIGLIO: errore nel cambio di codice\n"); // solo se execl fallisce
      exit(1);
   } else {                                          /* PADRE */
      printf("PADRE: wait\n");
      chpid = wait(NULL);
      printf("PADRE: PID DEL FIGLIO = %d\n", chpid);
      exit(0);
   }
}

/* programma prog */
void main(int argc, char *argv[]) {
   printf("PROG: PID = %d\n", getpid());
   printf("PROG: exit\n");
}

Esecuzione (supponendo che parta prima il padre):

PADRE: wait
FIGLIO: prima del cambio del codice
FIGLIO: PID = 4995
PROG: PID = 4995              ← stesso PID: exec non cambia processo
PROG: exit
PADRE: PID DEL FIGLIO = 4995

14. Esercizio conclusivo

01: main() {
03:    int i, j, k, m, stato;
04:    pid_t pid1, pid2;
05:    i = 10; j = 20; k = 30; m = 40;
06:    pid1 = fork();                     /* creazione del primo figlio */
07:    if (pid1 == 0) {                   /* PRIMO FIGLIO */
08:       j = j + 1;
09:       pid2 = fork();                  /* creazione del secondo figlio */
10:       if (pid2 == 0) {                /* SECONDO FIGLIO */
11:          k = k + 1;
12:          exit();
13:       } else {                       /* PRIMO FIGLIO */
14:          m = m + 1;
15:          wait(&stato);
16:          exit();
         }
18:    } else {                          /* PADRE */
19:       i = i + 1;
20:       wait(&stato);
21:       exit();
       }
22: }

Struttura: il padre crea il figlio 1, che crea il figlio 2 (nipote del padre). Ogni processo ha la sua copia delle variabili, presa nel momento della fork che l'ha creato.

Processo (es. PID)ijkmPerché
Padre (649)11203040fa solo i++
Figlio 1 (500)10213041copia del padre prima di i++; fa j++ e m++
Figlio 2 (501)10213140copia del figlio 1 dopo j++ ma prima di m++; fa k++
Commenti
  • L'ordine di terminazione è deterministico: secondo figlio → primo figlio → padre (perché il figlio 1 fa wait sul figlio 2, e il padre fa wait sul figlio 1).
  • L'ordine degli incrementi i++, j++, m++, k++ non è prevedibile (tranne che j++ viene prima di m++ e di k++, perché stanno nello stesso flusso prima della seconda fork).
Nota sul codice delle slide Le slide scrivono void main() ed exit() senza argomento per brevità. In C "vero" si usa int main(), exit(0) e si includono <stdlib.h> (per exit), <unistd.h> (per fork, getpid, execl) e <sys/wait.h> (per wait).

Riassunto

  • Il SO crea il parallelismo creando processi: esecutori completi, isolati tra loro (virtualizzazione).
  • I programmi accedono alle risorse solo tramite system call.
  • Processo = programma in esecuzione; PID unico; tutti hanno un padre tranne init; memoria = codice + dati + sistema.
  • fork(): copia il processo; restituisce 0 al figlio, PID del figlio al padre, −1 se errore. Dopo, ordine di esecuzione imprevedibile.
  • exit(n): termina con codice n (0 = ok). wait(&s): aspetta un figlio qualsiasi, restituisce il suo PID, exit code = s / 256. waitpid: aspetta un figlio preciso.
  • Zombie: figlio terminato il cui stato non è ancora stato raccolto dal padre.
  • execl(path, nome, arg…, NULL): cambia codice e dati, stesso PID, file aperti mantenuti; ritorna solo se fallisce.
  • fork + exec (+ wait): lanciare un altro programma mantenendo vivo il chiamante.
