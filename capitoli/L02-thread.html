Lezione 2

Thread

Cap. P2 delle dispense Pelagatti — cosa sono i thread, come si creano e terminano con la libreria pthread, e cosa condividono tra loro.

1. Cos'è un thread

Definizione Un thread è un flusso di controllo (cioè una sequenza di istruzioni eseguite una dopo l'altra) che può essere eseguito in parallelo con altri thread all'interno dello stesso processo.
  • Come i processi, i thread permettono a un programma di fare più cose in modo concorrente.
  • Un thread esiste solo dentro un processo. Quando lanci un programma, Linux crea un processo con un solo thread (il thread principale, cioè main), che esegue il programma in sequenza.
  • Quel thread può creare altri thread, che procedono in parallelo tra loro.
  • Il flusso di controllo di un thread è una funzione, che parte quando il thread viene creato.
  • Un thread è detto anche processo leggero (lightweight process) perché:
    • lo scambio di informazioni tra thread è facile (condividono la memoria);
    • per il SO gestire un thread costa meno che gestire un processo (meno strutture dati, meno lavoro).

Cosa condividono i thread

I thread dello stesso processo condividono tutto lo spazio di indirizzamento del processo tranne la pila (stack): ogni thread ha la sua pila. Per questo le variabili locali di una funzione eseguita da un thread appartengono solo a quel thread.

Perché li studiamo Non tanto per imparare l'API, ma per capire i problemi tipici della programmazione concorrente (che vedremo nella Lezione 3).

2. Esecuzione sequenziale vs concorrente

Sequenziale

Date due attività A e B, guardando il codice posso prevedere a priori se A verrà sempre prima di B (o viceversa).

Concorrente (parallela)

Guardando il codice NON posso prevedere se A verrà sempre prima di B o B prima di A.

L'esecuzione concorrente può essere:

  • Simulata — su un sistema mono-processore: i processi/thread si alternano sulla CPU a turno (time-sharing).
  • Reale — su un sistema multi-processore: girano davvero contemporaneamente su CPU diverse.

Per il programmatore il modello è lo stesso in entrambi i casi (il multi-processore va solo più veloce). E siccome di solito ci sono più thread che processori, anche su un multi-core il parallelismo è in parte simulato.

3. Granularità di un thread

La granularità è la quantità di istruzioni assegnata a ciascun thread:

  • poche istruzioni → più adatta al multithreading su mono-processore (n thread, 1 CPU);
  • centinaia/migliaia di istruzioni → più adatta al multi-processore (n thread, n CPU).

4. Thread POSIX (pthread)

Ci sono vari modelli di thread; noi usiamo lo standard POSIX (Portable Operating System Interface):

  • è un insieme di API del sistema operativo;
  • usando solo le API POSIX il programma è portabile su tutti i SO che le adottano;
  • funzioni e tipi per i thread sono dichiarati in <pthread.h>;
  • pthread = POSIX thread.

Pthread e processi

  • Un thread viene attivato dentro un processo; un processo può attivarne uno o più.
  • Quando il processo termina, terminano forzatamente tutti i suoi thread, ovunque si trovino.
  • Quindi bisogna garantire una terminazione coerente: il processo non deve finire prima che i suoi thread abbiano finito (→ pthread_join).

5. PID, Thread ID e TGID

Ogni pthread ha:

  • un thread ID di tipo pthread_t che lo identifica univocamente;
  • l'identificatore del processo che lo contiene, di tipo pid_t. getpid() chiamata da qualunque thread restituisce il PID del processo.

Il problema: internamente Linux dà un PID diverso a ogni processo, normale o leggero (cioè anche a ogni thread). Ma POSIX vuole che tutti i thread di un processo abbiano lo stesso PID. Soluzione: il Thread Group.

Thread Group e TGID
  • Un Thread Group è l'insieme dei thread (processi leggeri) che appartengono allo stesso processo.
  • Il TGID (Thread Group ID) è uguale al PID del thread group leader, cioè il primo thread del processo (quello di default, main).
  • Un processo con un solo thread ha quindi TGID = PID.
gettid()getpid()
Processo single-threadthread ID = PIDPID del processo = TGID

Da ricordare Nella terminologia Linux: getpid() restituisce in realtà il TGID; gettid() restituisce il "PID interno" del singolo thread.

6. Creazione: pthread_create

pthread_create() è l'analogo di fork(), con una differenza importante: al thread si passa il nome della funzione da eseguire (la thread function). Il nuovo thread parte sempre dall'inizio di quella funzione, qualunque sia il punto in cui si trova il creatore (con fork invece il figlio riparte dallo stesso punto del padre).

pthread_create(&tID1, NULL, &tf1, (void *) n);
#ParametroSignificato
1&tID1indirizzo di una variabile pthread_t dove verrà scritto l'ID del thread creato
2NULLpuntatore agli attributi; NULL = attributi di default
3&tf1indirizzo della funzione che il thread eseguirà
4(void *) nargomento passato alla funzione: uno solo, di tipo void *. Per passarne di più si crea una struct e se ne passa l'indirizzo

Thread principale

  • Quando un eseguibile viene lanciato, nel processo c'è un solo thread: il thread principale (o di default), cioè main().
  • main può creare altri thread con pthread_create, e qualsiasi thread può crearne a sua volta.
  • Appena un thread nuovo viene creato, creatore e creato sono in esecuzione concorrente.

7. Terminazione: pthread_join

  • Un thread termina quando esegue return o quando arriva alla fine della sua funzione.
  • Con il return può restituire un codice di terminazione (exit code) a chi lo ha creato: è semplicemente il valore restituito dalla thread function.
  • Il valore viene consegnato se e quando il creatore esegue pthread_join, che è l'analogo di waitpid(): aspetta la terminazione di uno specifico thread (va sempre indicato quale).
pthread_join(tID1, (void *) &thread_exit);
  1. tID1: il pthread_t del thread di cui attendere la fine;
  2. puntatore alla variabile che riceverà il codice di terminazione (NULL se non interessa).
// struttura tipica di una thread function
void * tf1 (void * arg) {
   // codice della funzione
   return (void *) valore_di_ritorno;
}

Esempio base

#include <pthread.h>
#include <stdio.h>

void * tf1 (void * tID) {
   int conta = 0;          /* variabile locale */
   conta++;
   printf("sono il thread n: %d; conta = %d\n", (int) tID, conta);
   return NULL;
}

int main (void) {
   pthread_t tID1, tID2;
   pthread_create(&tID1, NULL, &tf1, (void *) 1);  /* genera tID1 */
   pthread_create(&tID2, NULL, &tf1, (void *) 2);  /* genera tID2 */
   pthread_join(tID1, NULL);
   pthread_join(tID2, NULL);   /* main aspetta entrambi prima di uscire */
   return 0;
}

Entrambi i thread eseguono la stessa funzione tf1, ma con argomento diverso (1 e 2). Il numero viene "infilato" nel puntatore con un cast (void *) 1 e ricavato con (int) tID.

8. Thread e condivisione della memoria

  • Un thread gira nello spazio di indirizzamento del processo che l'ha creato → tutti i thread vedono la stessa memoria.
  • Ma ogni thread ha la propria pila, collocata a un indirizzo diverso dentro lo stesso spazio di indirizzamento:
    • variabili locali → allocate sulla pila → private del thread;
    • variabili globali e static → stanno nel segmento dati → condivise da tutti i thread.
Attenzione La condivisione rende facile scambiarsi dati, ma rende più difficile garantire che il programma sia corretto: due thread possono modificare la stessa variabile "insieme". È il tema della Lezione 3.

Variabile static locale È dichiarata dentro la funzione (quindi è visibile solo lì), ma conserva il valore tra una chiamata e l'altra perché non sta sulla pila. In pratica funziona come una globale ma con visibilità locale: quindi è condivisa tra i thread.

Nota: l'ordine delle due righe stampate non è prevedibile (esecuzione concorrente). Inoltre, nei casi globale/statica, conta++ su dato condiviso è proprio il tipo di operazione che può dare problemi (vedi istruzioni atomiche).

10. Passaggio di parametri e valore di ritorno

#include <pthread.h>
#include <stdio.h>

void *tf (void *arg) {
   int i = * ((int *) arg);   // cast: void* → int*, poi dereferenzio
   printf("sono thread_function: valore argomento = %d\n", i);
   i++;
   return (void *) i;          // exit code = 11
}

int main (void) {
   int argomento = 10;
   int thread_exit;
   pthread_t tID1;
   pthread_create(&tID1, NULL, &tf, &argomento);   // passo l'INDIRIZZO di argomento
   pthread_join(tID1, (void *) &thread_exit);     // ricevo il valore di ritorno
   printf("sono il main: thread_exit = %d\n", thread_exit);
   return 0;
}

Output:

sono thread_function: valore argomento = 10
sono il main: thread_exit = 11

Qui l'ordine è deterministico: il main stampa solo dopo la join, cioè dopo che il thread è terminato.

Riassunto

  • Thread = flusso di controllo dentro un processo; condivide tutto tranne la pila.
  • Concorrente = l'ordine tra due attività non è prevedibile dal codice; parallelismo simulato (time-sharing) o reale (multi-core).
  • pthread_create(&tid, NULL, funzione, arg) ≈ fork, ma il thread parte dall'inizio della funzione; un solo argomento void *.
  • pthread_join(tid, &ret) ≈ waitpid; serve a non far terminare il processo prima dei thread e a raccogliere il valore di ritorno.
  • getpid() = TGID (uguale per tutti i thread del processo), gettid() = ID del singolo thread.
  • Variabili locali: private. Globali e static: condivise → possibili interferenze.
